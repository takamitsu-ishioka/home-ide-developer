# AI Working Memory (Knowledge Base)

AIへ。

このディレクトリは、このマシン上の全プロジェクトを横断する「AI向け長期記憶」です。
人間は忘れます。AIは毎回読みます。だからここに書きます。

## 設計思想

- **木ではなくグラフ**：ディレクトリはフラット。分類フォルダは作らない。
  知識は複数の概念（例: Docker × Azure × WSL）にまたがるため、ツリー分類は
  「親は1つ」という前提が壊れた瞬間に破綻する。分類は `tags` で行う。
- **ファイル名は「発見」を書く**：現象ではなく解釈・因果関係を書く。
  `YYYY-MM-DD_<対象>_<発見>.md`
  - ✗ `2026-07-01_docker_desktop_error.md`（「何のエラー？」で終わる）
  - ✓ `2026-07-01_docker_desktop_destroys_wsl_dockerd_context.md`（因果関係が一瞬で分かる）
- **仮説には状態を持たせる**：確信度が変わったらファイル名ごと変える。
  - `hypothesis_...` → 検証中
  - `verified_...` → 確認済み
  - `refuted_...` → 否定された
- **frontmatterでグラフ構造を作る**：`tags` で横断検索、`related` で他ノードへのリンク（Zettelkasten）。

## ファイルの型

```markdown
---
id: KB-000001
tags:
  - Docker
  - WSL
related:
  - KB-000002
---

# 対象 + 発見（人間可読タイトル）

## 症状

## 原因（仮説 or 確定）

## 対処 / 復旧手順

## 検証方法

## 備考
```

## 運用ルール

- 復旧手順は**コピペで実行できる**形で書く。
  半年後の自分は「なぜ壊れたか」を10秒で知り、30秒で「対処」したい。
- 1ファイル1発見。複数の発見は複数ファイルに分ける（`related` でつなぐ）。
- `id` は連番（`KB-XXXXXX`）。新規作成時はこのディレクトリの既存ファイルの最大idを見て+1する。
- 新しいAIセッションはこのファイルを起点に、必要な `tags` / `related` を辿って関連知識を読む。
